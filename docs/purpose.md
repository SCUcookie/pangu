### 三、最终采用的技术路线（已确定，不再讨论）

你将 **严格按照以下技术组合实现**：

#### 核心创新组合（必须全部实现）

1. **多任务定制 Prompt 策略**

   * 针对 8 类教育任务分别设计 Prompt
   * 同一任务区分快 / 慢思考 Prompt
   * Prompt 完全工程化、模板化、可配置

2. **元认知反馈驱动的快慢思考动态调度**

   * 先快思考
   * 对快思考结果进行**自我评估**
   * 若置信度不足 → 自动触发慢思考
   * 慢思考完成后直接输出（不再回退）

3. **显式“认知路由器（Cognitive Router）”模块**

   * 将“是否继续思考”作为一等公民
   * 不再依赖人工规则判断难度

4. **轻量个性化解释风格（语言层面）**

   * 不做多模态
   * 仅通过 Prompt 控制解释详细度与教学语气
   * 作为增强而非核心评价指标

### 四、系统级架构（你必须据此重构）

你需要将 AgentV2 架构升级为以下逻辑流水线：

```
Input Question
      ↓
Task Type Identification
      ↓
Fast Prompt Inference (Fast Thinking)
      ↓
Meta-Cognitive Evaluation (Self-Evaluation)
      ↓
[Confidence Sufficient?]
      ↓ Yes                    ↓ No
Final Answer         Slow Prompt Inference (Slow Thinking)
                            ↓
                     Final Answer
```

#### 2️⃣ 元认知评估模块（核心创新）

在 `inference_engine.py` 中实现：

##### 快思考输出后，调用自我评估 Prompt：

固定使用以下策略（不可更改）：

* 使用同一个 Pangu 7B
* Prompt 内容为：

```
你刚才给出的答案是否完整、正确且可信？
请只回答以下三种之一：
- confident
- uncertain
- incorrect
```

##### 调度规则（唯一规则）：

* `confident` → 直接输出快思考答案
* `uncertain` 或 `incorrect` → 进入慢思考

这是**元认知反馈驱动机制**，是论文核心贡献之一。

---

#### 3️⃣ 慢思考推理机制（必须具备显式 CoT）

* Slow Prompt 必须：

  * 显式要求“逐步推理”
  * 先分析，再给最终答案
* 不做多轮反思
* 不做 Self-Consistency
* 控制 token 数在 2048 以内

---

#### 4️⃣ 个性化解释风格（增强模块）

在 Prompt 中加入以下参数控制：

* `explanation_level = {brief | detailed}`
* 默认使用 `detailed`

实现方式：

* 在 Prompt 文本中显式描述解释风格
* 不依赖用户画像模型
* 不引入外部记忆
